# A/B 整合记录

基于小组仓库 main 的 `9352086`。原 B 独立项目保留在上一级目录，本目录是可提交的小组整合版本。

## 最终实现关系

- `rsa_audit/`：队友的检测实现与原有命令入口，算法源码保持不变。
- `rsa_lab/detection.py`：薄适配层，实际调用 `rsa_audit.scan_keys`，不再维护第二套批量算法。
- `rsa_lab/datasets.py、crypto.py、evaluation.py、experiments.py、plots.py`：B 的生成、恢复、OAEP、独立评估、实验与绘图。
- `rsa_lab/cli.py`：完整攻击及修复演示。
- `presentation/final.html`：离线总展示，保留并嵌入 A 的三页动画，补充 B 的实测结果与演示。

## 已解决的接口差异

1. 公开 JSONL 统一为 n 的十六进制字符串、e 的 JSON 整数。B 读取器仍兼容历史 e 字符串，但新导出可由 A 直接读取。
2. A 的 `unresolved_full_overlap` 在 B 内部状态中映射为 `unresolved`，不会误标为正常。
3. 计时字段通过适配层转换，并保留 `conversion_seconds`。完整扫描时间来自 A 引擎，适配层输出格式转换不计入算法计时。
4. 去重、重复记录映射、不同 e 的私钥缓存规则保持一致。
5. A 的固定 OAEP 挑战由 B 的完整恢复模块解密，并以挑战自带的明文 SHA-256 验证。
6. 固定公钥文件使用 LF 行尾，`.gitattributes` 防止 Windows 克隆时换行变换破坏样本哈希。

## 验证

合并后 Python 测试共 70 项，包含 A 原有测试、B 测试和三个交接测试。完整 demo 使用 A 引擎，正确分解 5 个不同的 2048-bit 模数，解密 6 条 OAEP 记录。更换密钥后当前集合无共享因子。新增五类真实 2048 位集合的正负对照，两种算法共 10 次扫描与两项 OAEP 拒绝检查全部通过。

正式性能结果重新使用 A 引擎测量，不能拿原 B 独立检测器的数字当作本整合版本的结果。完成的扫描均在测量之后执行因子与明文核验。

## 提交范围

提交源码、测试、依赖、运行脚本、文档、固定公开 demo、整理过的 CSV 和图表。全量实验数据、真值、导出的私钥、环境和依赖安装包保留本地，不进入版本控制。

`artifacts/` 保存轻量结果和展示证据。`results/` 保存实际运行生成的新结果。`data/` 保存本地生成数据。初次克隆没有 data 时，demo 会新生成具有相同结构的样本；不能期待重新生成的随机素数或实测耗时与记录逐字相同。

## 建议的 Git 流程

本地 `b-integration` 分支先完成测试与审查，再推送同名分支并开草稿 PR。两人检查模块、演示和结论后合并到 main。提交已有测量时应保留对应配置和输入文件哈希。

归档文本统一使用 LF 行尾。公开 demo 的 manifest 和扫描报告使用归档文件的实际 SHA-256，`source_*` 字段保留原始运行输入的字节哈希。`EXPORT_MANIFEST.json` 可验证归档完整性，避免 Git 在不同平台转换行尾后造成哈希不一致。
