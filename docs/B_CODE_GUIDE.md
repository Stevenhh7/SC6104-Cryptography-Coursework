这份说明针对实际交付的完整实现，没有待填写的代码段。先运行 demo，再沿下面的顺序阅读函数。

整合版的检测来自队友的 `rsa_audit`。`rsa_lab/detection.py` 是接口转换层，乘积树和余数树直接复用 A 的实现。新公开 JSONL 的 e 为整数，B 读取器仍兼容旧版 e 字符串。性能计时采用 A 的字段并单列算术后端转换阶段。

## 1. 一条数据怎样成为可恢复密钥

生成器让两个模数使用同一个素数 p：n1=p*q1，n2=p*q2。公钥文件只保留 id、n、e。A 的检测给 B 一个非平凡因子。B 检查它确实整除 n，并验证两个因子都是不同素数，再重建私钥并解密 OAEP。

**核心文件是 `rsa_lab/crypto.py` 的 `recover_private_key`。**

```python
p = factor
q = n // p
lambda_n = lcm(p - 1, q - 1)
d = pow(e, -1, lambda_n)
key = RSA.construct((n, e, d, p, q), consistency_check=True)
```

这五步分别完成：选择已知因子、恢复另一因子、计算 Carmichael 函数、求乘法逆元、构建标准 RSA 私钥对象。这里的 `pow(e, -1, lambda_n)` 是模逆，不是普通的倒数，也不是 e 的负一次方浮点运算。

对于两个不同素数，lambda(n)=lcm(p-1,q-1)。RSA 私钥满足 e*d≡1 mod lambda(n)。常见教材用 phi(n)=(p-1)(q-1) 求逆，同样可以产生有效私钥。我们采用计划指定的 lambda(n)。不同合法表示的 d 不一定数值相同，因此正确性应检查模逆关系与加解密，而不能要求与另一软件导出的 d 字符串相同。

函数前面的检查不能省掉：factor=1 或 n 没有提供分解；不能整除 n 说明结果有误；q 是合数说明它不是本项目支持的二素数 RSA；p=q 是平方模数；e 与 lambda(n) 不互素时不存在模逆。`consistency_check=True` 再由标准库检查密钥组件的一致性。

## 2. OAEP 的参数在哪里

`oaep_cipher` 显式设置 SHA-256，MGF1 也使用 SHA-256，label 由公开密文文件给出。默认 label 为空字节串。

公钥用来加密，重建的私钥用来解密。`decrypt_message` 先确认公开的算法名称、Base64 与密文长度，再调用 OAEP 解密。OAEP 会验证编码结构，损坏的密文或不同 label 会报错。

2048 位 RSA 有 256 字节模数，SHA-256 的 OAEP 最大明文长度为 256-2*32-2=190 字节。这里加密的是很短的演示消息，没有把 RSA 当成大文件加密工具。

**答辩要点：OAEP 保护编码和填充，私钥一旦恢复，攻击者就可以像合法接收者一样解密。**我们的演示是真实 OAEP 解密，没有用裸 RSA 模幂替代。

## 3. 数据生成器如何控制弱点

`PrimeSource.next` 调用 cryptography 的 OpenSSL RSA 生成原语，从生成的密钥组件中取出素数。它使用密码学随机源，不用 Python 的固定 seed 生成素数。取出素数以后，我们自己控制如何组合成实验模数。

`PrimeSource.pair` 检查 p!=q 和乘积的真实 bit_length。两个 1024 位素数相乘可能只有 2047 位，所以最终必须检查乘积，不能仅检查因子位数。

`create_records` 有四个模型：

- normal：所有因子独立产生。
- pairs：按固定间隔安排共享 p 的密钥对，其他因子独立产生。
- demo：一对共享 p 的密钥、一个三角结构、正常密钥，再加入两个重复记录。
- pool：从有限素数池选择一个因子，另一个因子独立产生。

demo 的三角结构是 a*b、a*c、b*c。每个模数的两个因子都能在其他模数中找到，所以批量 GCD 返回整个模数。这个结构特意验证 A 的回退代码。重复的弱公钥在恢复结果中多出一条成功记录，但不会增加不同模数的数量。

pool 模型的 seed 只决定选择哪个槽位。固定 seed 不能复现新的素数，所以我们保存完整实验数据。弱素数池模拟某一种弱生成方式，没有复现真实设备启动时熵不足的全部过程。

## 4. 为什么要独立真值

`save_dataset` 输出公开输入、公钥加密产生的密文，以及包含 p、q、原始消息的秘密真值。攻击函数不接收真值路径。

`actual_truth` 按不同模数建立每个素数的所有者集合。如果一个素数属于两个不同模数，它就形成可利用的共享关系。同一个 n 出现两次，所有者集合仍只有一个 n，因此不会被当作可恢复关系。

`evaluate` 在攻击结束后重新从真值推导预期集合，并检查公钥文件摘要。它不信任“normal”“weak”等标签。有效结果要同时满足：预期的不同模数全部得到正确因子、没有多报、没有遗漏，并且恢复的明文与真值一致。

**答辩要点：秘密信息仅用于构造样本与攻击完成后的核验，没有进入检测与恢复函数。**公开输入独立运行测试对此做了额外验证。

## 5. 实验计时如何保证可比

每次扫描在全新的子进程中运行，输入加载完成后才开始扫描计时。两算法读取同一份数据，使用同一个算术后端。完整 scan 时间包含去重、主算法、回退和结果组装。

算法计时不包括素数生成、文件读写、OAEP 解密和真值核验。这些步骤仍然真实执行，只是不混入扫描耗时。原始 CSV 每次重复一行，中位数在 summary.csv 中。

`peak_rss_bytes` 由操作系统提供，测量整个扫描进程的峰值常驻内存，包含导入和输入。它不是仅统计 Python 对象的大小。超时作用于整个子进程，启动与写文件也计入超时限额，但成功的扫描秒数仍按函数内部计时。

不能把批量 GCD 简单称为 O(m)。乘积树中大整数越来越长，乘法和求余成本取决于位数。回退可能增加很多两两 GCD，所以在三角结构多的集合中需单独解释这个成本。

## 6. B 也要能解释 A 的树算法

乘积树将输入两两相乘，得到总乘积 P。余数树从顶层向下传递父余数，对子节点乘积的平方取模，最终得到每个 P mod n_i²。

设 P=n_i*Q_i，则 P mod n_i² 仍是 n_i 的倍数。除以 n_i 后，得到与 Q_i 在模 n_i 下同余的数，因此 gcd(n_i,r_i/n_i)=gcd(n_i,Q_i)。直接对 n_i 取模只会得到 0。

奇数个节点的最后一个子节点原样上移。下降时根据 i//2 找父节点。空集没有树；单元素 P=n，余数 n，最终 gcd(n,1)=1。

g=1 表示当前集合没有检测到共享关系。1<g<n 表示非平凡因子。g=n 表示两个因子都可能在集合其他位置出现，去重后仍可能发生，必须进一步拆分。

## 7. 修复演示的含义

`repair_public` 根据公开扫描结果更换受影响模数，使用新的独立随机素数。原本属于同一个重复模数的记录保持对应关系。程序还用新私钥对新密文做合法 OAEP 往返检查。

更换后，攻击程序仍然只读取新的公开输入和密文。它没有检测到共享因子，因而不能用这一攻击恢复新的私钥。已有旧私钥被攻破后，旧密文不会因为换钥而自动变安全。

## 8. 常见问答

| 问题 | 回答 |
|---|---|
| 为什么 2048 位仍然很快被分解？ | 两个模数有共享因子，求 GCD 不需要执行通用大整数分解。 |
| 只有一个弱公钥能否这样攻击？ | 集合中需要另一个具有非平凡共享因子的模数；覆盖不足会漏掉现实中的弱关系。 |
| 重复公钥为什么没有直接给出 p？ | gcd(n,n)=n，只有整个模数，没有拆分。 |
| OAEP 是否被破解？ | 私钥恢复后正常 OAEP 解密，实验没有破坏 OAEP 本身的数学安全性。 |
| 返回 q 而不返回 p 会不会错？ | 两个因子都能用于恢复，评估接受任意一个正确素因子。 |
| 为什么成功记录数和模数数不同？ | 重复记录也有密文，但同一个 n 只算一个不同模数。 |
| 是否直接调用现成攻击工具？ | 检测、树结构、去重、回退和实验流程在项目中实现，库用于底层算术及标准密码原语。 |
| 未发现共享因子是否等于安全？ | 只能说明当前集合没有检测到这一类结构。 |
